# Directives (read by bin/tbx). Written WITHOUT the colon here on purpose —
# with it, this legend parses as a directive and wins over the real values
# below. That is exactly what happened on 2026-08-12.
#   tbx-image   <ref>    container base image
#   tbx-export  <names>  binaries to expose on the host PATH via ~/.local/bin
#   tbx-home    <path>   own home instead of sharing ~ (omit to share; absolute)
#   tbx-nvidia  yes|no   pass the host NVIDIA driver in. CREATE-TIME ONLY —
#                        changing it on a built box does nothing until you
#                        `tbx rm` and recreate. tbx warns when you try.
#
# tbx-image: registry.fedoraproject.org/fedora-toolbox:44
# tbx-nvidia: yes
# jupyter is NOT in the export list: it isn't in the package list, so the export
# only ever printed a warning. Add the package first if you need it, then the
# binary here — an export list that names things that don't exist trains you to
# ignore its warnings.
#
# latexmk and pdflatex removed from the export list 2026-08-20 (ADR-0018): TeX Live
# is Tier 1 on the host now, so a wrapper in ~/.local/bin would shadow /usr/bin and
# silently build host documents inside the box, against the box's fonts. Same failure
# as the exported python3 in the tiering runbook. Do not re-add.
#
# Jupyter is deliberately NOT exported. Run `jupyter lab` inside the box and open
# the localhost URL in the host browser — the network namespace is shared, so this
# needs no wrapper and no export. One less shadowed binary.
# tbx-export: gcc g++ make cmake node npm

# The libraries themselves (numpy, pandas, matplotlib, scikit-learn, opencv,
# tensorflow/keras, pyspark) are pip installs into a per-subject venv, NOT dnf
